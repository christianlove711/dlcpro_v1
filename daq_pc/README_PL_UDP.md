# AD9269 纯 PL UDP 采集界面

## 启动

双击 `启动统一采集界面.bat`，或在 `C:\Users\chris\dlcpro_v1` 执行：

```powershell
python app.py --open-adc
```

最终版只支持 AD9269 双通道。PC 连续监视支持 `5/10/20 MSPS`；`40/80 MSPS`
只供 PS/Linux 的 Scope DMA 或 Event DMA 使用，PL UDP 会明确拒绝。

## 网络

- PL 板卡：`192.168.20.2`
- PC 的 PL 专用网卡：`192.168.20.1/24`
- 控制/状态：UDP 5000
- 原始数据：UDP 5001
- PS/DLCpro 网口继续使用 `192.168.10.x`

当前 PL 协议栈不响应 ARP/ICMP，因此 `ping 192.168.20.2` 失败不能说明板卡
离线。GUI 使用 `/24` 广播发现，并校验回复源地址、事务号和 `stream_id`。

20 MSPS 双通道的有效载荷约 80 MB/s，建议把 Realtek PL 网卡的
`Jumbo Packet` 设置为 `9014 Bytes`。GUI 会在启用约 9 KB 巨帧前检查网卡。

## 示波器和录制

通道 A/B 使用独立低负载窗口，支持：

- 时基、2/5/10/20 FPS、实时/较慢滚动；
- 原始码或电压显示、自动/手动量程；
- 上升沿/下降沿软件触发、冻结；
- 短窗口三次插值显示，长窗口自动切换 min/max 包络。

时基范围为 `0.1 µs/div` 到 `1 s/div`。短时基直接显示原始样点；长时基
使用独立的 1 ms min/max 历史缓存，最多保留约 20 秒，因此在 20 MSPS
下显示 1 Hz 扫频时不会每帧重复处理数千万个原始样点。

插值仅影响显示，不改变 UDP 原始数据、触发判断或 CSV。点击“开始 CSV
录制”后，接收线程把完整 AD9269 UDP 数据块直接送入后台二进制临时文件，
不再通过绘图环形缓冲或受 FPS 限制。录制前可选择“A+B 同文件”“仅 A”
“仅 B”或“A/B 分开文件”；单通道模式的高速临时文件占用约减半。点击
“结束并保存 CSV”时才选择最终路径，随后流式转换为 CSV；分开文件模式会
自动生成带 `_A.csv`、`_B.csv` 后缀的两个文件。

20 MSPS 双通道原始数据约为 80 MB/s；CSV 文本通常会膨胀到数百 MB/s，
因此停止后的转换可能需要一段时间和较大的磁盘空间。界面的“录制队列丢样”
只表示本机磁盘持续写入速度不足导致后台队列满，不再把绘图抽样算成录制丢失。

状态计数含义：

- `丢包`：PC 检测到 UDP 序号空洞。
- `PL 监视丢样`：PL 原始监视 FIFO 来不及发送的样点。
- `事件未启用`：Linux 尚未提交 Event DMA 描述符并武装，PL主动抑制事件帧。
- `DDR 背压丢帧`：Event DMA 已武装后，因真正拥塞无法写入的事件帧。
